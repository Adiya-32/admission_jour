# Компас — персональный маршрут поступления

**Живой продукт:** [kompas-admission.netlify.app](https://kompas-admission.netlify.app) — вход не требуется, доступен всем.

Проект для **LOCUS Startup Hackathon 2026, Кейс 02** (код участия `LOCUSCASE2`).

Компас превращает короткую анкету абитуриента в понятный маршрут поступления: диагностику профиля,
минимум три подходящие программы с объяснением «почему подходит», сравнение вариантов и пошаговый
план действий с отслеживанием прогресса.

## Задача

Абитуриенту нужен не ещё один список университетов, а маршрут: куда поступать, почему конкретный
вариант подходит именно ему и что делать следующим шагом. Информация о поступлении разрознена,
а типичные рекомендации слишком общие.

## Аудитория

Ученик 9–11 класса (СНГ/Казахстан), выбирающий между бакалавриатом в Казахстане и популярными
зарубежными направлениями (Турция, Южная Корея, Германия, Польша, Венгрия, Великобритания).

## Решение и пользовательский путь

1. **Вход** — объяснение ценности сервиса.
2. **Профиль** — анкета: класс, интересы, средний балл, английский, языки, ЕНТ/IELTS, страны,
   бюджет, сроки, стипендия/общежитие. При выборе широкого направления (например, «Информационные
   технологии») дополнительно предлагается уточнить фокус (например, «Data Science и AI» или
   «Кибербезопасность») — это делает совпадение по интересам точнее, а не просто по общей категории.
3. **Диагностика** — резюме профиля, сильные стороны и ограничения, сформулированная цель.
4. **Рекомендации** — минимум 3 программы, отранжированные по совпадению, с прозрачным списком
   причин «почему подходит» и «на что обратить внимание». У каждой программы можно раскрыть карточку
   с репутацией вуза в целом и в выбранной сфере, честным списком сильных и слабых сторон, атмосферой
   кампуса и тем, кто там преподаёт — не только формальные цифры, но и контекст для решения.
5. **Сравнение** — таблица минимум по двум выбранным программам (страна, стоимость, язык, требования,
   дедлайны, стипендии, общежитие).
6. **Маршрут** — план по категориям (экзамены, документы, дедлайны, академические шаги, активности)
   с выделенным следующим шагом и чекбоксами прогресса.

При изменении любого ключевого ответа в анкете (бюджет, страна, интересы, баллы) рекомендации и
маршрут пересчитываются заново — это можно проверить, вернувшись на шаг «Профиль» и изменив ответ.

## Стек

- **React 19 + TypeScript + Vite** — SPA.
- **React Router (HashRouter)** — навигация между этапами, подходит для статического хостинга без бэкенда.
- **Tailwind CSS v4** — дизайн-система (цвета, типографика, карточки, чипы, состояния) через `@theme`.
- **Без сервера и без LLM-ключей**: рекомендации строит прозрачный rule-based движок
  (`src/engine/recommend.ts`), а не чёрный ящик — это соответствует пункту кейса «разрешён
  rule-based подход» и упрощает объяснимость для пользователя и проверку жюри.
- **Хранение данных** — `localStorage` в браузере (профиль, прогресс, избранные для сравнения);
  ничего не отправляется на сервер.

## Архитектура

```
src/
  types.ts              — типы профиля, программ, рекомендаций, шагов маршрута
  data/
    programs.ts          — демо-датасет из 37 вузов/программ по 23 странам, включая уровень
                            селективности (ориентировочный % принятых) по каждой программе
    constants.ts          — списки интересов, стран, языков
  engine/
    recommend.ts          — скоринг программ по профилю + генерация объяснений (match/caution)
    diagnosis.ts           — построение диагностики (сильные стороны / ограничения / цель)
    roadmap.ts              — генерация пошагового плана на основе профиля и топ-программ
  state/
    AppContext.tsx           — React Context + persist в localStorage (профиль, прогресс, сравнение)
  components/                — переиспользуемые UI-примитивы (Button, Chip, Badge, Layout, Stepper)
  pages/                      — Landing, ProfileForm, Diagnosis, Recommendations, Compare, Roadmap
```

Рекомендательный движок — чистая функция `getRecommendations(profile) → Recommendation[]`: считает
баллы по 5 весовым критериям (направление, бюджет, страна, готовность по языку/баллам, сроки) и
возвращает список с человекочитаемыми причинами. Это позволяет продукту оставаться предсказуемым
и объяснимым, и легко расширяется добавлением новых программ в `data/programs.ts` без изменения логики.

## Данные и источники

Данные о вузах в `src/data/programs.ts` — **демонстрационные**, собраны из открытой информации
официальных сайтов вузов (ссылки указаны в карточке каждой программы и в датасете). Точные суммы,
пороги баллов и даты дедлайнов ориентировочные и могут отличаться от актуальных на сайте вуза —
это явно указано в интерфейсе и в README, как того требует кейс.

## AI / API

В MVP используется **rule-based** рекомендательный движок без обращения к внешним LLM API — весь расчёт
происходит в браузере, детерминирован и легко объясним. Архитектура допускает замену/дополнение
движка вызовом LLM (например, для генерации более гибких формулировок объяснений) без изменения
остального приложения — для этого достаточно заменить реализацию `engine/recommend.ts`, оставив
контракт `Profile → Recommendation[]`.

## Ограничения

- Демо-режим: без сервера, без реальной аутентификации, без реальной подачи документов в вузы.
- Датасет ограничен 37 программами по 23 странам — репрезентативная выборка для демонстрации, не полный каталог.
- Точность дедлайнов и порогов баллов — ориентировочная, требует проверки на сайте вуза перед реальной подачей.

## Готовые компоненты

- UI-примитивы написаны с нуля (без сторонних UI-kit), стилизация — Tailwind CSS v4.
- Библиотеки: `react-router-dom` (роутинг), `clsx` (классы), `framer-motion` (установлена, зарезервирована
  под будущие анимации перехода между шагами).
- Шрифты Google Fonts: Inter, Space Grotesk.

## Тестовый сценарий (для проверки жюри)

1. На главной нажать «Начать за 5 минут».
2. Заполнить анкету: имя, класс, 1–2 интереса, средний балл, английский, страны, бюджет → «Получить диагностику».
3. Проверить, что диагностика отражает введённые данные (сильные стороны/ограничения меняются в зависимости от ответов).
4. На «Рекомендациях» убедиться, что показано минимум 3 программы с объяснением причин.
5. Отметить 2–3 программы чекбоксом «Добавить к сравнению» → «Сравнить выбранные» → проверить таблицу.
6. Перейти к «Маршруту», отметить прогресс по шагам, убедиться, что «Следующий шаг» обновляется.
7. Вернуться на «Профиль», изменить бюджет или страну → убедиться, что рекомендации и маршрут заметно меняются.
8. Проверить мобильную версию (сузить окно браузера) — путь и навигация остаются рабочими.
